# SMProxy 认证机制总结

## 项目概述

SMProxy 是一个基于 MySQL 协议和 Swoole 开发的轻量级数据库连接池代理服务器。它作为伪装的 MySQL 服务端，能够被标准的 MySQL 命令行客户端连接，实现数据库连接池和读写分离功能。

## 架构设计

### 核心组件

1. **SMProxyServer**: 主服务器类，处理客户端连接和认证
2. **FrontendAuthenticator**: 前端认证器，处理客户端认证
3. **BackendAuthenticator**: 后端认证器，管理与真实 MySQL 服务器的连接
4. **MySQLPool**: 连接池管理器，维护数据库连接
5. **协议包处理器**: 处理 MySQL 协议包的编解码

## 认证流程详解

### 1. 握手阶段 (Handshake)

当客户端连接到 SMProxy 时，服务器发起握手过程：

```php
// FrontendAuthenticator::getHandshakePacket()
$rand1 = RandomUtil::randomBytes(8);
$rand2 = RandomUtil::randomBytes(12);
$this->seed = array_merge($rand1, $rand2);

$hs = new HandshakePacket();
$hs->packetId = 0;
$hs->protocolVersion = Versions::PROTOCOL_VERSION; // 10
$hs->serverVersion = Versions::SERVER_VERSION;     // "5.5.8-SMProxy"
$hs->threadId = $server_id;
$hs->seed = $rand1;
$hs->serverCapabilities = $this->getServerCapabilities();
$hs->serverCharsetIndex = CharsetUtil::getIndex(CONFIG['server']['charset']);
$hs->serverStatus = 2;
$hs->restOfScrambleBuff = $rand2;
```

**服务端能力标志**:
- CLIENT_LONG_PASSWORD
- CLIENT_FOUND_ROWS
- CLIENT_LONG_FLAG
- CLIENT_CONNECT_WITH_DB
- CLIENT_PROTOCOL_41
- CLIENT_INTERACTIVE
- CLIENT_TRANSACTIONS
- CLIENT_SECURE_CONNECTION

### 2. 认证阶段 (Authentication)

#### 客户端认证包解析

SMProxy 支持多种认证包格式：

1. **标准认证包 (AuthPacket)**:
   - 客户端标志 (clientFlags)
   - 最大包大小 (maxPacketSize)
   - 字符集索引 (charsetIndex)
   - 用户名 (user)
   - 密码 (password)
   - 数据库名 (database)
   - 插件名 (pluginName)

2. **快速认证响应 (20字节)**: 直接密码验证
3. **插件认证响应 (14字节)**: 插件切换

#### 密码验证逻辑

SMProxy 使用 MySQL 原生认证算法：

```php
// SecurityUtil::scramble411()
$pass1 = getBytes(sha1($pass, true));
$pass2 = getBytes(sha1(getString($pass1), true));
$pass3 = getBytes(sha1(getString($seed) . getString($pass2), true));

// XOR 操作
for ($i = 0; $i < count($pass3); ++$i) {
    $pass3[$i] = ($pass3[$i] ^ $pass1[$i]);
}
```

#### 认证验证

```php
private function checkAccount($server, $fd, $user, $password)
{
    $checkPassword = $this->source[$fd]->checkPassword($password, CONFIG['server']['password']);
    return CONFIG['server']['user'] == $user && $checkPassword;
}
```

### 3. 认证插件支持

SMProxy 支持以下认证插件：

- **mysql_native_password**: 默认认证插件
- **sha256_password**: SHA256 密码认证 (部分支持)
- **caching_sha2_password**: 缓存 SHA2 密码认证

当客户端请求不支持的插件时，SMProxy 会发送认证切换包，要求客户端使用 `mysql_native_password`。

## 连接池管理

### 后端连接认证

当需要连接到真实的 MySQL 服务器时，BackendAuthenticator 设置客户端能力标志：

```php
public static function getClientFlags()
{
    $flag = 0;
    $flag |= Capabilities::CLIENT_LONG_PASSWORD;
    $flag |= Capabilities::CLIENT_FOUND_ROWS;
    $flag |= Capabilities::CLIENT_CONNECT_WITH_DB;
    $flag |= Capabilities::CLIENT_PROTOCOL_41;
    $flag |= Capabilities::CLIENT_SECURE_CONNECTION;
    $flag |= Capabilities::CLIENT_PLUGIN_AUTH;
    return $flag;
}
```

### 连接生命周期

1. **初始化连接**: Worker 启动时预创建连接
2. **连接获取**: 从连接池获取空闲连接
3. **连接使用**: 执行 SQL 查询
4. **连接回收**: 查询完成后放回连接池
5. **连接清理**: 定时清理空闲超时的连接

## 总结

SMProxy 通过完全兼容 MySQL 协议，实现了作为一个伪装服务端的认证机制。它不仅提供了基础的用户名密码认证，还支持插件认证和连接池管理，为高并发场景下的数据库访问提供了高效稳定的解决方案。

在未来重写过程中，应重点考虑模块化设计、增强安全特性以及更好的可扩展性，以满足更多企业级应用的需求。
